# Operating the complete archive

The frozen snapshot contains 1,396,719 unique assets, 1,396,720 logical placements,
27,980 source listing pages and 408,135,188,823 advertised original bytes. Listing
pages are not PDF/OCR pages. No media-page count or complete OCR size is inferred.
The current corpus has 250 source PDFs, one page each; this sample is concentrated
in Data Set 1 and cannot predict the rest of the archive or recognition accuracy.

## Capacity and acceptance gates

Keep workspace, payloads, queues, image scratch, model responses and immutable
exports on an existing external filesystem. Reserve at least original bytes plus
observed derived data, largest bounded concurrent scratch, export copies and a
free-space margin. The current 512 MiB input, page/pixel/ZIP expansion and scratch
caps are admission limits; larger documents remain explicit blocked work until
reviewed limits/streaming support are configured and tested. Do not silently omit
them or raise memory globally. A missing/replaced volume must stop work.

Use the immutable inventory to enumerate each dataset and media type. Before
unattended operation, add a separate stratified batch covering large/multipage PDFs,
poor scans, tables, handwriting, photographs, ZIP depth and supported text formats.
Select it deterministically and record source SHA/membership; request authorization
before actual download/provider work. Compare page coverage, transcripts and exact
evidence with originals, not only job success. Measure pages/hour, calls/page,
retry fraction and bytes/page under the configured FCC route. Forecast the full
archive only after those measurements and record confidence/unsupported strata.

Use a single writer per downloader/corpus, durable leases and bounded work limits.
Resume with the same inventory/layout and pinned extraction, model, prompt/schema
and routing versions. Review failed/blocked jobs before retry; cooldowns are not
completed work. Current free-only FCC route supports bounded image/text Messages;
audio/video transcription and Office conversion require separately implemented
and tested adapters. Do not treat their raw bytes as page OCR or claim support.

## Completion and publication

Track inventory certification, download audit, selected source membership,
inspection/page coverage, canonical text, chunk/synthesis completion, review flags
and approvals separately. Full download requires the fresh full-source audit,
not a 250-file pilot audit or a process exit. Re-freeze after source mutations.
Public exports include only explicitly approved imported documents. Preserve
unsupported, blocked, missing and private pending-review totals alongside the
published Viewer; none may be hidden in a percentage called complete.

Publish immutable bundles and activate them as a pair of database/clusters plus
canonical TXT. Preserve source-to-member mappings and evidence offsets. The full
source catalogue stays browsable while processing proceeds; graph queries and
browser payloads remain bounded. Re-export reviewed batches rather than making
the UI read the live job queue. A full-archive public coverage certificate remains
unavailable until all declared source/processing/review gates pass. The existing
250-file private bundle proves the workflow, not whole-archive processing.
